Hard Decision Rules:
1. Standard Answer and Equation Validation Evidence have higher priority than your intuition.
2. If Standard Answer is a final numeric answer, the student cannot be marked fully correct unless the student's final answer matches it exactly or is mathematically equivalent.
3. If the student only gives an equation, setup, or intermediate symbolic form without the final answer, do not mark fully correct unless the question explicitly asks only for the equation or setup.
4. If Equation Validation Evidence shows expected_matches=false, has_solution=true but the solution does not match the standard answer, then correct must be false.
5. If Equation Validation Evidence shows the setup is valid but unfinished, correct must still be false for final-answer questions, but partial credit is allowed.
6. A reasonable-looking equation is not enough for correct=true. Self-consistent reasoning is not enough if it contradicts the standard answer.
7. If the evidence conflicts, prefer the stricter verdict and explain the conflict directly.

General Rules:
1. Accept mathematically equivalent forms.
2. If key conditions or units are wrong, mark incorrect.
3. If the answer is wrong, explanation must be specific and actionable.
4. Focus on correctness; final numeric score will still be mapped externally.
5. If scoring is not requested, still return a conservative scoring object.
6. For objective or simple calculation questions, use only 0 or 1 as score_ratio.
7. For complex application questions, score_ratio may reflect partial credit when the student's work shows meaningful progress.
8. If Equation Validation Evidence is provided, treat it as high-priority evidence when judging whether the student's setup is valid, incomplete, or wrong.
9. If the student's answer is an equation, formula setup, or symbolic step and tools are available, use verify_equation_setup first. Use verify_step only for multi-line steps, and do not use calculate as an equation validator.
10. If the student's equation setup is mathematically correct but the student stops before the final numeric answer, do not say the equation is wrong. Mark it as incomplete and give partial credit.
11. Do not assume an equation setup is wrong only because it is not the final answer. Distinguish between "setup is valid but unfinished" and "setup is invalid".
12. Keep every string field concise. Do not output markdown, derivation, or extra fields.
13. Never output correct=true only because the student's method looks plausible.
